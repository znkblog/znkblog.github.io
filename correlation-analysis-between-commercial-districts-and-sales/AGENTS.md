# 프로젝트 작업 지침

## 공통 작업 원칙

- 런타임은 Python 3.10 이상, 프로젝트·가상환경·의존성 관리는 `uv`를 사용합니다. 의존성 선언은 `pyproject.toml`, 잠금은 `uv.lock`, 설치·동기화는 `uv sync`, 스크립트 실행은 `uv run .\<스크립트>.py`로 합니다.
- 스크립트에서 CSV 입출력과 CLI에는 Python 표준 라이브러리(`csv`, `argparse`, `pathlib`, `tempfile`)를 우선 사용합니다. 외부 라이브러리는 `pyproject.toml`에 선언하고 `uv.lock`을 갱신합니다.
- 스크립트는 실행 순서에 맞춰 번호를 붙입니다. 인코딩 변환은 `01_convert_to_utf8.py`, 격자 집계는 `02_analyze_restaurant-grids.py`, 매출 격자 매칭은 `03_attach_sales_to_grids.py`입니다.
- 원본 파일 `식품_일반음식점.csv`는 약 680MB이므로 수정하지 마세요. 대용량 CSV는 전체를 메모리에 올리지 말고 스트리밍 또는 청크 단위로 처리하세요.
- `README.md`는 사용자가 직접 작성한 파일입니다. 사용자가 명시적으로 요청하지 않는 한 수정하지 마세요.
- 사용자가 질문만 한 경우에는 질문에 답하고, 파일 수정이나 스크립트 실행은 명시적으로 요청한 경우에만 하세요.
- 스크립트는 입력·출력 경로를 CLI 인자로 바꿀 수 있게 하고, 별도 지정이 없으면 아래 기본 파일명을 사용합니다. 원본과 결과 경로가 같아 원본을 덮어쓰지 않게 보호하고, 결과 파일은 임시 파일에 완성한 뒤 교체합니다.
- 결과 CSV는 별도 요청이 없는 한 Excel에서 한글이 올바르게 보이도록 UTF-8-SIG(BOM 포함)과 `newline=""`로 기록합니다.

## CSV 인코딩 변환

- `01_convert_to_utf8.py`의 기본 입력은 `식품_일반음식점.csv`, 기본 출력은 `식품_일반음식점_utf-8.csv`입니다. 위치가 다르면 `[source] [output]` 인자로 지정할 수 있습니다.
- `--source-encoding`이 주어지면 그 인코딩을 사용합니다. 지정하지 않으면 먼저 파일 시작의 UTF-32/UTF-8/UTF-16 BOM을 확인하고, BOM이 없을 때 `charset-normalizer`로 파일 앞 2MiB만 검사해 원본 인코딩을 추정합니다. 자동 감지는 표본 기반 추정이므로 애매하거나 감지할 수 없는 파일은 인코딩을 직접 지정하세요.
- 디코딩 오류는 `errors="strict"`로 처리합니다. 잘못된 바이트를 조용히 대체하지 말고 실패를 알리며, 실패한 변환의 임시 파일을 정리합니다.
- 입력은 1MiB씩 읽고, 출력은 UTF-8 바이트와 파일 시작의 BOM으로 기록합니다. CSV 필드나 행을 파싱·재직렬화하지 않아 내용 및 줄바꿈 바이트는 유지하며, 문자 인코딩만 변환합니다.
- 의존성: `charset-normalizer`. 실행 예: `uv run .\01_convert_to_utf8.py`, `uv run .\01_convert_to_utf8.py .\원본.csv .\결과.csv --source-encoding cp949`.

## 음식점 좌표 격자 집계

- `02_analyze_restaurant-grids.py`의 기본 입력은 `식품_일반음식점_utf-8.csv`, 기본 출력은 `격자배치결과.csv`입니다. `[source] [output]` 인자로 경로를 바꿀 수 있습니다.
- `영업상태명`을 앞뒤 공백 제거 후 `영업/정상`과 정확히 비교합니다. 일치하는 행만 처리하며 `좌표정보(X)`, `좌표정보(Y)`의 앞뒤 공백을 제거해 숫자로 변환합니다. 비어 있거나 숫자가 아니거나 유한수가 아닌 좌표는 제외하고 건수를 알립니다. 매출 격자 스크립트와 달리 좌표의 EPSG 범위 검증은 하지 않습니다.
- 좌표값은 이미 보정계수 미적용 Bessel 중부원점TM(EPSG:5174)이라고 가정하고 변환하지 않습니다. 입력을 한 번 스트리밍해 유효 좌표 범위를 구하고, 두 번째 순회로 격자별 개수를 집계합니다.
- 격자 크기는 1000m입니다. 격자 시작 X는 `floor(min_x / 1000) * 1000`, 시작 상단 Y는 `ceil(max_y / 1000) * 1000`입니다. X 셀은 `[왼쪽 X, 오른쪽 X)`, Y 셀은 `(아래쪽 Y, 위쪽 Y]`로 배정합니다. 따라서 경계 좌표는 각 방향에서 정확히 한 셀에 포함됩니다.
- 전체 좌표 범위를 덮는 직사각형 격자 전체를 출력하며 음식점이 없는 셀도 개수 0으로 포함합니다. 각 행에는 격자의 좌상단 X와 좌상단 Y를 기록합니다. ID는 위에서 아래 행 우선, 각 행에서 왼쪽에서 오른쪽 순으로 `G000001`부터 부여합니다. 열은 `격자ID`, `격자좌상단좌표정보(X)`, `격자좌상단좌표정보(Y)`, `음식점카운팅` 순서입니다.
- 메모리는 입력 전체가 아니라 격자별 집계에 사용합니다. 유효 좌표가 하나도 없으면 헤더만 있는 결과를 기록합니다. `uv run .\02_analyze_restaurant-grids.py`로 실행합니다.

## 매출 좌표 격자 매칭

- `03_attach_sales_to_grids.py`의 기본 입력은 `매출정보.csv`와 `격자배치결과.csv`, 기본 출력은 `격자매출배치결과.csv`입니다. `[sales] [grids] [output]` 인자로 경로를 바꿀 수 있습니다.
- 격자 CSV는 `csv.DictReader`로 한 번 읽어 메모리의 `(격자 좌측 X, 격자 하단 Y) -> (격자ID, 음식점카운팅)` 사전에 보관합니다. 필수 헤더와 값, 중복 격자를 검증하며, 빈 격자 파일은 오류로 처리합니다.
- 매출 CSV는 한 행씩 읽습니다. `매출액`, X, Y 문자열의 앞뒤 공백을 제거하고 WGS84(EPSG:4326)의 X=경도, Y=위도로 해석합니다. 경도 `[-180, 180]`, 위도 `[-90, 90]` 범위를 벗어나거나 좌표가 비었거나 숫자·유한수가 아니면 제외하고 좌표 오류 건수를 알립니다.
- `pyproj.Transformer.from_crs("EPSG:4326", "EPSG:5174", always_xy=True)`로 격자 좌표계에 변환합니다. 격자 산출과 동일하게 X는 왼쪽 포함·오른쪽 미포함, Y는 아래쪽 미포함·위쪽 포함 경계를 사용합니다. 격자에 매칭되지 않는 행은 조용히 결과에서 제외하며 요약에 격자 범위 밖 건수를 표시합니다.
- 매출액은 숫자로 변환하거나 격자별 합산하지 않습니다. 앞뒤 공백을 제거한 원래 문자열을 각 매출 행마다 출력하고, 해당 격자의 `격자ID`, `음식점카운팅`을 붙입니다. 출력 열은 `매출액`, `격자ID`, `음식점카운팅` 순서입니다.
- 매출 데이터 전체를 메모리에 올리지 않습니다. 출력은 UTF-8-SIG이며, 실행은 `uv run .\03_attach_sales_to_grids.py`입니다. 의존성은 `pyproj`입니다.

## 매출액과 음식점 밀도 상관관계 발표 자료

- 사용자가 요청한 경우에만 `격자매출배치결과.csv`를 분석해 한 장의 PPTX를 직접 만듭니다. 산점도는 X축 매출액, Y축 음식점 밀도(음식점 수/1km²)로 표시합니다. 실제 데이터에서 Pearson·Spearman 상관계수, Pearson p값, 표본 수를 계산해 제시하고 상관관계를 인과관계로 해석하지 않습니다.
- 분포의 0값과 극단값을 점검하고 전체 범위와 밀집 구간을 구분해 보여줍니다. 한글 글꼴을 지정하고 텍스트 자동 줄바꿈을 설정합니다. 생성 후 PPTX를 다시 열어 슬라이드 수와 주요 문구·결과물을 검증합니다.
- 상관 통계에 사용한 분석 도구가 의존성에 포함되지 않은 경우에만 `uv run --with ...`로 일시 설치할 수 있습니다. 프로젝트 의존성에 영구 추가할 필요가 없으면 `pyproject.toml`을 불필요하게 바꾸지 않습니다.
