## 정렬

서로의 크기를 비교할 수 있는 요소들로 채워진 어떤 데이터셋이 있을 때, 이 요소들을 오름 또는 내림차순으로 순서를 세우는 것을 정렬이라고 함,

알고리즘에서 정렬을 얘기할 때는 시간복잡도 (time complexity) 와 안정성 (stability) 가 같이 언급됨,

시간복잡도는 얼마나 빠르게 정렬을 수행하는가와 관련되어 있고, 보통은 O(n^2) 또는 O(n log n) 정도의 시간복잡도를 보인다고 함, 내 수준에선 O(n^2) 은 이중루프로 구현, O(n log n) 은 이중루프보다는 좀 더 효율적인 방법으로 구현 정도로 느껴졌음,

안정성은 정렬의 결과 동일한 크기를 가진 요소들 끼리 원래의 순서를 보장하느냐로 판단함, 예를들어 python 의 튜플 요소로 이뤄진 데이터셋 A 가 아래와 같이 있다고 해보면...

```python
A = [ (5, "감자"), (7, "옥수수"), (1, "옥수수"), (3, "감자"), (1, "고구마") ]
```

A 를 튜플 첫번째 요소인 숫자 기준으로 오름차순 정렬을 했을 때, `(1, "옥수수")` 와 `(1, "고구마")` 처럼 동일한 크기를 가지는 요소들이 정렬 이후에도 항상 원래의 순서가 유지되는 정렬일 때 안정 정렬이라 함,

만일 정렬의 결과로 `[ (1, "고구마), (1, "옥수수), ... ]` 처럼 동일한 크기를 가진 요소 순서가 뒤바뀔 가능성이 조금이라도 있다면 불안정 정렬 이라고 함,

대부분의 프로그래밍 언어에서는 합병정렬 (아래참고) 를 베이스로 한 시간복잡도 O(n log n) 이면서 안정정렬인 정렬 알고리즘을 기본으로 지원한다고 함,

leetcode 912. Sort an Array ([https://leetcode.com/problems/sort-an-array/](https://leetcode.com/problems/sort-an-array/)) 는 숫자 데이터셋을 주고 이를 오름차순으로 정렬해보라는 문제임,

문제에 보면 시간복잡도 O(n log n) 으로 풀으라고 되어있어, O(n^2) 의 경우는 시간초과 에러 발생,

아래부터는 다양한 정렬을 사용한 풀이인데, 대체로 본인이 이해하기 쉬웠던 순으로 소개함,

## 버블 정렬

시간복잡도 O(n^2), 안정 정렬임,

> - 데이터셋 A 의 A[0] 과 A[1] 비교, A[0] > A[1] 인 경우 두 값을 스왑 (즉 큰 값을 뒤쪽으로 보냄)
> - 다음으로 A[1] 과 A[2] 를 비교하고 스왑, A[2] 와 A[3] 를 비교하고 스왑, ... A[n-1] 과 A[n] 을 비교하고 스왑 
> - 위 첫번재 단계의 결과, A 에서 가장 큰 값은 A[n] 에 위치하게 됨
> - 다시 처음으로 돌아가서 A[0] 과 A[1] 비교 스왑부터 다시 실행, ... A[n-2] 와 A[n-1] 까지 비교하고 스왑 (가장 큰 값이 제일 뒤에 있기 때문에 n-1 까지만 비교 스왑)
> - 두번째 단계의 결과, A 에서 두번째로 큰 값은 A[n-1] 에 위치하게 됨
> - 다음 단계 계속 진행...

아래는 이를 pyton 코드로 구현,

```python
class Solution:
    def sortArray(self, nums: List[int]) -> List[int]:
        for i in range(0, len(nums)):
            swapped = False

            for j in range(0, len(nums)-i-1):
                if nums[j] > nums[j+1]:
                    nums[j], nums[j+1] = nums[j+1], nums[j]
                    swapped = True

            if not swapped:
                break

        return nums
```

이중루프 사용, 앞 요소가 뒤 요소보다 클 경우만 스왑이 일어나기 때문에, 동일한 크기의 요소끼리는 순서 변화가 없어 안정 정렬임,

i 순회 구문은 `단계`를, j 순회 구문은 각 요소의 `비교 스왑`을 담당, 만일 어떤 단계에서 스왑이 한번도 일어나지 않았다면, 그 단계에서는 순서륿 바꿔줄 요소가 없다는 뜻인데, 그 이후의 단계에서도 없을 것이므로 그 시점에 종료하면 됨, swapped 변수로 스왑이 한번이라도 일어났는지 체크,

## 선택 정렬

시간복잡도 O(n^2), 불안정 정렬임,

> - 데이터셋 A 에서, A[0] ~ A[n] 까지 가장 작은 값이 위치한 인덱스 k 를 찾아 a[k] 와 a[0] 을 스왑
> - 위 첫번째 단계의 결과, 가장 작은 값이 A[0] 에 위치
> - 이번에는 A[1] ~ A[n] 까지 가장 작은 값이 위치한 인덱스 k 를 찾아 a[k] 와 a[1] 을 스왑
> - 두번째 단게의 결과, 두번째로 작은 값이 A[1] 에 위치
> - 다음 단계 계속 진행...

아래는 python 으로 코드 구현한 결과임,

```python
class Solution:
    def sortArray(self, nums: List[int]) -> List[int]:
        for i in range(0, len(nums)-1):
            minidx = i

            for j in range(i+1, len(nums)):
                if nums[j] < nums[minidx]:
                    minidx = j

            nums[i], nums[minidx] = nums[minidx], nums[i]

        return nums
```

이중루프로 구현, j 순회를 하면서 가장 작은 값이 위치한 인덱스를 minidx 변수가 계속 업데이트 하다가, 순회 종료 후 스왑하는 방식임,

멀리 떨어진 요소끼리 스왑하는 구조이기 때문에, 불안정 정렬이 됨, 예를들어...

```python
A = [ (5, "A"), (5, "B"), (2, "C") ]
```

가 있고, 튜플의 앞 숫자를 기준으로 오름차순 선택정렬을 한다고 하면...

첫번째 단계에서 `(5, "A")` 와 `(2, "C")` 가 스왑이 되고, 이 경우 동일한 크기인 `(5, "A")` 와 `(5, "B")` 의 순서가 바뀜, 즉 동일한 크기 요소끼리 본래의 순서를 유지할 수 없는 케이스가 발생할 수 있기에 불안정 정렬임,
