## 분할정복

아주아주 많은 원소를 포함하고 있는 데이터셋이 있다고 해봄, 어떤 문제를 해결하기 위해 데이터셋 전체를 가지고 뭔가를 하는 게 부담이 될 수 있으니, 일단 자르고, 자르고, ..., 잘라서 부분문제로 만든다음, 부분문제에서 문제를 해결하고, 해결된 부분문제끼리 합쳐 다시 해결하고, 다시 합쳐 해결하고, ..., 다시 합쳐 해결해서 최종적으로 문제를 풀어내는 방법임, 정확한 개념은 [나무위키](https://namu.wiki/w/%EB%B6%84%ED%95%A0%20%EC%A0%95%EB%B3%B5%20%EC%95%8C%EA%B3%A0%EB%A6%AC%EC%A6%98)를 참고해보기 바람,

이해가 잘 안된다면 이렇게 생각해볼 수 있음, 100 명이 하는 가위바위보 게임이 있고 최종 탈락자 1 명을 골라내기로 함, 100 명이 한번에 가위바위보 하면 언제 승부가 날지 몰라 아래와 같이 게임하기로 함,

일단 50 명씩 조를 나눔, 그리고 25 명씩 나눔, ... 계속 나눔, 각 조가 1 명이 될때까지 나눈 뒤, 이제 조끼리 모여가며 가위바위보함, 이제 진 사람끼리 다시 모여 가위바위보 하고, 다시 모여 가위바위보, ... , 하다보면 이 방식의 가위바위보 게임 횟수는 우연이 아니고서야 100 명이 한번에 가위바위보 하는 것보다는 훨씬 적을 것이고 그만큼 최종 탈락자를 가려내는 데 효율적일 것임,

이런 방식으로 문제를 해결하는 것이 분할정복임,

## 코드 구현

가위바위보를 가만히 생각해보면, 조를 나누는 것(데이터셋을 자름), 조에서 진사람 끼리 다시 가위바위보(부문문제 해결) 로 볼 수 있음, 그리고 데이터셋을 자르고, 부문문제 해결이라는 방식이 연속적으로 반복되기 때문에 **보통 재귀함수 형식**으로 구현함,

일반적으로 분할정복을 수행하는 재귀함수 내부는 아래와 같이 세부분으로 나눠 볼 수 있음,

```markdown
- 더 이상 A 를 자를 수 없을 때 리턴하는 부분
- A 를 두 부분으로 잘라서 재귀호출하는 부분
- 두 부분의 재귀호출 결과를 다시 문제해결하여 리턴하는 부분
```

가위바위보 게임이라고 하면 아래와 같이 나타낼 수 있음,

```python
def 가위바위보(조):
    # '조' 안의 인원수가 1 이라면, 더이상 나눌 수 없으므로 그 '조'에 속한 인원을 리턴
    if len(조) == 1:
        return 조[0]

    # '조' 인원수를 반절씩, 앞조와 뒷조로 나눠서 재귀호출
    m = len(조) // 2
    앞조결과 = 가위바위보(조[:m])
    뒷조결과 = 가위바위보(조[m:])

    # 앞조결과(앞조에서 진 사람) 와 뒷조결과(뒷조에서 진 사람) 끼리 다시 가위바위보게임을 하고 진 사람을 리턴
    return 게임(앞조결과, 뒷조결과)
```

재귀함수 흐름을 따라가다보면 분할정복이 이해가 될 것임,

## leetcode: 912. Sort an Array

[https://leetcode.com/problems/sort-an-array/](https://leetcode.com/problems/sort-an-array/)

주어진 nums 데이터셋을 오름차순으로 정렬해서 리턴하는 문제임, 다양한 정렬 방법이 있고, 그 방법들은 대부분 [다른 포스팅](/blog/sort-algorithm) 에 소개를 했음,

그런데, 분할정복을 사용하는 정렬 방법들은 여기서 소개함, 바로 합병 정렬과, 퀵 정렬임, (아래에 안정/불안정 정렬이라는 게 언급되는데, 뭔지 궁금하다면 해당 링크 먼저 참고하기 바람)

## 합병 정렬

시간복잡도 O(n log n), 안정 정렬임,

> - 데이터셋 A 길이가 1 이라면, A 를 그대로 리턴, 아니라면 둘로 나눠서 재귀호출하고 각각의 결과를 A1, A2 로 받음
> - A1 과 A2 각 원소를 비교해가면서, A1 과 A2 의 원소가 모두 오름차순으로 포함된 새로운 데이터셋을 만들어서 리턴

아래는 이 알고리즘을 python 코드로 나타낸 풀이임,

```python
class Solution:
    def sortArray(self, nums: List[int]) -> List[int]:
        return mergeSort(nums)

def mergeSort(nums: List[int]) -> List[int]:
    if len(nums) == 1:
        return nums

    m = len(nums) // 2
    lnums = mergeSort(nums[:m])
    rnums = mergeSort(nums[m:])

    a = []
    l, r = 0, 0
    while l < len(lnums) and r < len(rnums):
        if lnums[l] <= rnums[r]:
            a += lnums[l],
            l += 1
        else:
            a += rnums[r],
            r += 1
    if l < len(lnums):
        a += lnums[l:]
    elif r < len(rnums):
        a += rnums[r:]

    return a
```

분할정복 알고리즘으로 구현되어 있음,

lnums, rnums 은 재귀호출의 결과이며, 둘 모두 오름차순으로 정렬이 되어있는 부분 데이터셋임, 새로운 데이터셋 a 를 만들어, lnums 와 rnums 를 비교해가면서 a 를 채운 뒤 리턴하는 방식임,

참고로 while 아래 if 구문 조건식을 보면, `lnums[l] <= rnums[r]` 으로 되어 있는 것을 확인할 수 있음, 동일한 크기일 때도 해당 구문이 True 가 되는데, lnums 의 값을 a 반영하도록 되어 있음, lnums 가 rnums 보다 본래 앞쪽에 위치한 데이터셋이기 때문에, 동일한 크기일 때 앞쪽의 데이터셋을 우선하도록 되어있다는 뜻이고 이 때문에 안정 정렬이 됨,

## 퀵 정렬

시간복잡도 O(n log n), 그러나 이미 정렬된 데이터셋에서 제일 마지막이나 첫번째 원소를 pivot 으로 고를 경우 O(n^2) 이 될 수도 있음, 무조건은 아니지만 대체로 불안정 정렬임,

가장 기본적인 알고리즘은 아래와 같음,

> - 데이터셋 A 에서, 어떤 원소를 pivot 으로 설정,
> - A 안에서 pivot 보다 작거나 같은 원소값을 앞쪽에, pivot 보다 큰 원소값을 뒤쪽에 두고, 그 사이에 pivot 을 위치시킴,
> - pivot 앞 뒤로 다시 재귀호출하여 위 과정을 반복,

위 알고리즘 구현한 python 풀이는 아래와 같음,

```python
class Solution:
    def sortArray(self, nums: List[int]) -> List[int]:
        return quickSort(nums)

def quickSort(nums: List[int]) -> List[int]:
    if len(nums) <= 1:
        return nums

    pivot = nums[-1]
    lnums = quickSort([x for x in nums[:-1] if x <= pivot])
    rnums = quickSort([x for x in nums[:-1] if x > pivot])

    return lnums + [pivot] + rnums
```

nums 의 가장 마지막 원소를 pivot 으로 설정, 그리고 `x <= pivot` 구문으로 인해 동일한 크기 원소끼리 원래의 순서를 유지할 수 있어, 이 경우는 안정 정렬이 됨, 하지만 시간초과로 문제는 풀리지 않았음,

이 방식은 pivot 중심으로 데이터셋을 나누어 재귀호출을 하는 퀵 정렬의 정의와 분할정복 개념에도 부합하지만, 퀵 정렬은 보통 in-place 방식을 더 많이 사용하고, 데이터셋을 나누는 방법에 따라 여러 종류가 있음,

더 자세한 것은 ai 에게 물어보거나, [나무위키](https://namu.wiki/w/%EC%A0%95%EB%A0%AC%20%EC%95%8C%EA%B3%A0%EB%A6%AC%EC%A6%98#s-4.2.3)를 참고해볼 것,

## leetcode: 53. Maximum Subarray

[https://leetcode.com/problems/maximum-subarray/](https://leetcode.com/problems/maximum-subarray/)

숫자 원소로 채워진 nums 데이터셋이 있을 때, 연속된 원소들의 합(부분합) 중에서 최대 부분합을 구하는 문제,

보통 [다른 포스팅](/blog/kadane-algorithm) 에서 소개한 kadane 알고리즘과 같은 동적 계획법으로 해결할 수 있으나, 분할정복으로도 가능함,

위에서 설명한 가위바위보를 분할정복 관점으로 생각하면, 데이터셋을 최대한 나눈 다음에 합쳐가면서 가위바위보 게임을 계속해 감, 이 문제도 데이터셋을 최대한 나눈 다음에, 합쳐가면서 최대 부분합을 계속 구해나가면 됨,

먼저 잘 이해하고 있어야할 점이 있는데, 결론부터 얘기하면 재귀호출을 반복하면서 리턴해야하는 값은 최대 부분합만이 아님, 아래와 같이 천천히 생각해 보면 됨,

예를들어 각각 X, Y 데이터셋을 합친 X+Y 의 최대 부분합은, 기존 X 의 최대 부분합 (Xm 이라함) 또는 기존 Y 의 최대 부분합 (Ym 이라함) 이 될 수 있는데, 한가지가 더 있음,

예를들면 아래와 같은 데이터셋이라면...

```plaintext
X                  Y
[4, 2, 3, -20, 7], [3, 2, -20, 5, 5]
```

Xm 은 9, Ym 은 10 임, 그러나 X+Y 라면 최대 부분합은 12 가 됨, (X 의 가장 오른쪽인 7 부터 시작해서, Y 의 3, 2 까지 더한 값)

12 는 X 의 어딘가부터 시작해서 X 의 가장 오른쪽까지 이어진 최대 부분합 (Xr 이라함) 과 Y 의 가장 왼쪽부터 Y 의 어딘가까지 이어진 최대 부분합 (Yl 이라함) 의 합임,

즉 X+Y 의 최대 부분합은 `max(Xm, Xr+Yl, Ym)` 이 됨,

X+Y 의 최대 부분합은 이제 다른 데이터셋 (예를들면 Z+W) 과의 최대 부분합을 계산하는 다음 단계에 들어가며, 이젠 `max((X+Y)m, (X+Y)r+(Z+W)l, (Z+W)m)` 을 구해야 함,

수식을 자세히 보면 (X+Y)r 이 있음, (X+Y)r 은 X+Y 데이터셋의 어딘가부터 시작해서 X+Y 의 가장 오른쪽까지 이어진 최대 부분합으로, `max(Xr+Yt, Yr)` 이 됨, 참고로 Yt 는 Y 데이터셋의 전체 합계임,

(Z+W)l 은 Z+W 데이터셋 가장 왼쪽부터 Z+W 의 어딘가까지의 최대 부분합임, `max(Zl, Zt+Wl)` 이 됨, 여기에도 전체 합계를 나타내는 Zt 가 있음,

종합하면 분할정복 과정에서 다음 단계로 넘겨야 할 정보들은 어떤 데이터셋 A 기준으로, A 의 가장 왼쪽 원소부터의 최대부분합 Al, A 의 현시점 최대 부분합 Am, A 의 가장 오른쪽 원소를 포함한 최대 부분합 Ar, A 원소의 전체합계 At 가 필요함, (처음에는 이해하기 매우매우 어려움)

아래는 이를 python 코드로 나타낸 풀이임

```python
class Solution:
    def maxSubArray(self, nums: List[int]) -> int:
        return f(nums)[1]

def f(nums: List[int]) -> (int, int, int, int):
    if len(nums) == 1:
        return nums[0], nums[0], nums[0], nums[0]

    m = len(nums) // 2
    Xl, Xm, Xr, Xt = f(nums[:m])
    Yl, Ym, Yr, Yt = f(nums[m:])

    return max(Xl, Xt+Yl), max(Xm, Xr+Yl, Ym), max(Xr+Yt, Yr), Xt+Yt
```

f 함수가 분할정복을 수행하는 재귀함수 임, 리턴값은 순서대로 왼쪽 원소부터의 최대 부분합, 데이터셋의 최대 부분합, 가장 오른쪽 원소를 포함하는 최대 부분합, 전체 데이터셋의 합계를 나타냄,

리턴값의 두번째 원소가 전체 데이터셋의 최대 부분합이므로, 최종 결과로 두번째 원소만을 리턴함,
