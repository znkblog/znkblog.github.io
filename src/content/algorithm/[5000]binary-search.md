## 이진탐색

데이터셋에서 보통 원하는 값을 찾고자 할 때는, 제일 앞에 위치한 데이터부터 순차적으로 검색을 해야 함,

이 방식은 운이 나쁘면 원하는 값을 아주 늦게 찾을 수밖에 없음,

엑셀에서 사용하는 VLOOKUP 함수를 "정확히 일치" 옵션을 주고 사용하면, 범위에서 특정 값을 순서대로 검사해가며 찾게 되는데, 엑셀이 거슬릴 정도로 느려진 경험을 해본 적이 많았음,

만일 데이터셋이 **오름차순**으로 정렬이 되어있다면, 특별한 알고리즘으로 원하는 데이터를 빠르게 찾을 수 있음,

[나무위키](https://namu.wiki/w/%EC%9D%B4%EC%A7%84%20%ED%83%90%EC%83%89)를 보면, 이진탐색 알고리즘 설명이 있는데, 설명을 모두 볼 필요없이 중간에 있는 그림만 봐도 이진탐색이라는 게 이런 알고리즘이구나라는 걸 쉽게 알 수 있음,

그리고 왜 데이터셋이 사전에 오름차순으로 정렬이 되어있어야하는지도 이해가 될 것임,

## 코드 구현

찾고자 하는 값을 `target`, 데이터 셋을 `A` 라고 한다면, 대체로 아래와 같이 식으로 찾게 됨,

> - A 전체 범위에서 중간에 위치한 값 middle 을 구함,
> - middle 과 target 을 비교,
> - middle < target 이라면 middle 포함 그 아래를 모두 버리고, middle > target 이라면, middle 포함 그 위를 모두 버림,
> - 버리지않고 남긴 데이터들만으로 A 를 다시 정의하고, 위 단계를 반복,
> - 반복의 결과, middle == target 이면 원하는 값을 찾은 것이고, A 데이터셋이 하나의 요소만 남았을 때까지도 target 을 찾지 못했다면 애초에 target 이 A 에는 없던 것임,

위와 같은 알고리즘 원리는 머릿속에 쉽게 이해가 되지만, 이를 코드로 실제 구현하려고 해보니 생각보다 쉽지가 않았음,

[leetcode](https://leetcode.com/) 코딩테스트 사이트에 순수하게 이진탐색 알고리즘을 구하라는 문제가 있어, 아래 문제풀이에서 코드를 구현함

## leetcode: 35. Search Insert Position

[https://leetcode.com/problems/search-insert-position/](https://leetcode.com/problems/search-insert-position/)

오름차순으로 주어진 배열에서, 오름차순을 해치지 않고 특정 값의 위치(인덱스)를 찾거나 또는 특정 값이 들어갈 수 있는 위치를 찾는 문제임,

위에 언급한 이진탐색 알고리즘 원리를 다시금 생각해보면, `target` 을 끝까지 못찾았을 때는 `A` 데이터셋에서 제일 마지막까지 남아있는 데이터의 위치가 `target` 이 들어갈 수 있는 위치가 됨,

`target` 을 찾는 과정에서 버려지는 값들과 `target` 의 크기관계를 생각하면 그렇게 될 수밖에 없음,

아래는 그 풀이임,

```python
class Solution:
    def searchInsert(self, nums: List[int], target: int) -> int:
        i, j = 0, len(nums)

        while i < j:
            m = i + (j-i) // 2

            if nums[m] < target:
                i = m + 1
            else:
                j = m

        return i
```

위 코드에서 `i` 와 `j` 는 데이터셋에 해당하는 `nums` 의 버려지지않은 채 아직 남아있는 요소들의 범위를 가리키는 값으로, **`i` 이상, `j` 미만으로 정의**,

`m` 은 중간 위치를 구하고 있으며, `target` 과 중간 위치의 값인 `nums[m]` 를 비교, 필요없는 부분을 버리는 동작을 `i` 와 `j` 값을 조정하는 것으로 대신함,

참고로 `i` 이상 `j` 미만으로 범위를 정의한다고 했기 때문에, if 구문 안의 `i` 와 `j` 의 범위 조정 수식에 차이가 있음,

위와 알고리즘은 끝까지 반복이 계속되는 경우, **반드시 무조건 `i == j` 가 되는 시점이 발생**하게 됨, 그리고 이 때의 `i` 또는 `j` 의 값이 `target` 이 들어갈 수 있는 위치를 가리키도록 되어 있음,

재밌는 건, 반복문 중간에 `target` 을 찾았더라도 그 위치를 리턴하지 않고 계속 반복을 진행하는 데, 만일 아래와 같이 데이터셋이 있는 경우에도 작동이 되어야 하기 때문임,

```python
target = 7
nums = [2, 3, 5, 7, 7, 7, 7, 7, 7, 11, 13]
```

코드에서 if 구문은 `target == nums[m]` 인 경우 `j` 를 조정하게 됨, 즉 `m` 위치보다 뒤에 있는 숫자들을 버리는 셈이 되며, 바로 위 케이스 에서는 반복문 종료가 되었을 때는 `i` 또는 `j` 는 7 들이 모여있는 구간의 제일 앞 위치인 3 이 됨,

만일 `target == nums[m]` 일 경우 `i` 를 조정하도록 바꾼다면, 결과는 7 들이 모여있는 구간의 제일 뒤 다음칸인 9 가 됨,

참고로 python 은 이진탐색을 해주는 빌트인 함수가 별도로 있으며, 이를 사용해서 문제를 풀 수도 있음,

```python
class Solution:
    def searchInsert(self, nums: List[int], target: int) -> int:
        return bisect_left(nums, target)
```

본래 bisect 라이브러리를 임포트해야 하나, leetcode 에서는 자동으로 임포트를 해줌,

[bisect](https://docs.python.org/ko/dev/library/bisect.html) 라이브러리에 포함된 함수들과 명세는 링크 참고 바람,
