## 정렬

서로의 크기를 비교할 수 있는 원소들로 채워진 어떤 데이터셋이 있을 때, 이 원소들을 오름 또는 내림차순으로 순서를 세우는 것을 정렬이라고 함,

알고리즘에서 정렬을 얘기할 때는 시간복잡도 (time complexity) 와 안정성 (stability) 이 같이 언급됨,

시간복잡도는 얼마나 빠르게 정렬을 수행하는가와 관련되어 있고, 보통은 O(n^2) 또는 O(n log n) 정도의 시간복잡도를 보인다고 함, 내 수준에선 O(n^2) 은 이중루프로 구현, O(n log n) 은 이중루프보다는 좀 더 효율적인 방법으로 구현 정도로 느껴졌음,

안정성은 정렬의 결과 동일한 크기를 가진 원소들 끼리 원래의 순서를 보장하느냐로 판단함, 예를들어 python 의 튜플 원소로 이뤄진 데이터셋 A 가 아래와 같이 있다고 해보면...

```python
A = [ (5, "감자"), (7, "옥수수"), (1, "옥수수"), (3, "감자"), (1, "고구마") ]
```

튜플 숫자 기준으로 오름차순 정렬을 했을 때, `(1, "옥수수")` 와 `(1, "고구마")` 처럼 동일한 크기를 가지는 원소들이 정렬 이후에도 항상 원래의 순서가 유지되는 정렬일 때 안정 정렬이라 함,

만일 정렬의 결과로 `[ (1, "고구마), (1, "옥수수), ... ]` 처럼 동일한 크기를 가진 원소 순서가 뒤바뀔 가능성이 조금이라도 있다면 불안정 정렬 이라고 함,

대부분의 프로그래밍 언어에서는 정렬을 위한 빌트인 함수를 제공하는데, 보통은 합병정렬 (아래참고) 를 베이스로 한 시간복잡도 O(n log n) 이면서 안정인 정렬함수가 지원됨,

leetcode 912. Sort an Array ([https://leetcode.com/problems/sort-an-array/](https://leetcode.com/problems/sort-an-array/)) 는 숫자로 이뤄진 데이터셋을 주고, 이를 오름차순으로 정렬해보라는 문제임,

문제에 보면 시간복잡도 O(n log n) 으로 풀으라고 되어있어, O(n^2) 의 경우는 보통 에러가 발생함,

아래부터는 다양한 정렬을 사용한 풀이인데, 대체로 본인이 이해하기 쉬웠던 순으로 소개함, (그리고 in-place 방식, 즉 공간복잡도 O(1) 이 가능한 케이스도 있으나 굳이 공간효율성까지 철저히 고려하지는 않았음)

## 버블 정렬

시간복잡도 O(n^2), 안정 정렬임,

> - 데이터셋 A 의 A[0] 과 A[1] 비교, A[0] > A[1] 인 경우 두 값을 스왑, (즉 큰 값을 뒤쪽으로 보냄)
> - 다음으로 A[1] 과 A[2] 를 비교하고 스왑, A[2] 와 A[3] 를 비교하고 스왑, ... A[n-1] 과 A[n] 을 비교하고 스왑,
> - 위 첫번재 단계의 결과, A 에서 가장 큰 값은 A[n] 에 위치하게 됨,
> - 다시 처음으로 돌아가서 A[0] 과 A[1] 비교 스왑부터 다시 실행, ... A[n-2] 와 A[n-1] 까지 비교하고 스왑, (가장 큰 값이 제일 뒤에 있기 때문에 n-1 까지만 비교 스왑)
> - 두번째 단계의 결과, A 에서 두번째로 큰 값은 A[n-1] 에 위치하게 됨,
> - 다음 단계 계속 진행...

아래는 이를 pyton 코드로 구현,

```python
class Solution:
    def sortArray(self, nums: List[int]) -> List[int]:
        for i in range(0, len(nums)):
            swapped = False

            for j in range(0, len(nums)-i-1):
                if nums[j] > nums[j+1]:
                    nums[j], nums[j+1] = nums[j+1], nums[j]
                    swapped = True

            if not swapped:
                break

        return nums
```

이중루프 사용, 앞 원소가 뒤 원소보다 클 경우만 스왑이 일어나기 때문에, 동일한 크기의 원소끼리는 순서 변화가 없어 안정 정렬임,

i 순회 구문은 "단계"를, j 순회 구문은 각 원소의 "비교 스왑"을 담당, 만일 어떤 단계에서 스왑이 한번도 일어나지 않았다면, 그 단계에서는 순서륿 바꿔줄 원소가 없다는 뜻인데, 그 이후의 단계에서도 없을 것이므로 그 시점에 종료하면 됨, swapped 변수로 스왑이 한번이라도 일어났는지 체크,

## 선택 정렬

시간복잡도 O(n^2), 불안정 정렬임,

> - 데이터셋 A 에서, A[0] ~ A[n] 까지 가장 작은 값이 위치한 인덱스 k 를 찾아 a[k] 와 a[0] 을 스왑,
> - 위 첫번째 단계의 결과, 가장 작은 값이 A[0] 에 위치,
> - 이번에는 A[1] ~ A[n] 까지 가장 작은 값이 위치한 인덱스 k 를 찾아 a[k] 와 a[1] 을 스왑,
> - 두번째 단게의 결과, 두번째로 작은 값이 A[1] 에 위치,
> - 다음 단계 계속 진행...

아래는 python 으로 코드 구현한 결과임,

```python
class Solution:
    def sortArray(self, nums: List[int]) -> List[int]:
        for i in range(0, len(nums)-1):
            minidx = i

            for j in range(i+1, len(nums)):
                if nums[j] < nums[minidx]:
                    minidx = j

            nums[i], nums[minidx] = nums[minidx], nums[i]

        return nums
```

이중루프로 구현, j 순회를 하면서 가장 작은 값이 위치한 인덱스를 minidx 변수가 계속 업데이트 하다가, 순회 종료 후 스왑하는 방식임,

멀리 떨어진 원소끼리 스왑하는 구조이기 때문에, 불안정 정렬이 됨, 예를들어...

```python
A = [ (5, "A"), (5, "B"), (2, "C") ]
```

가 있고, 튜플의 앞 숫자를 기준으로 오름차순 선택정렬을 한다고 하면...

첫번째 단계에서 `(5, "A")` 와 `(2, "C")` 가 스왑이 되고, 이 경우 동일한 크기인 `(5, "A")` 와 `(5, "B")` 의 순서가 바뀜, 즉 동일한 크기 원소끼리 본래의 순서를 유지할 수 없는 케이스가 발생할 수 있기에 불안정 정렬임,

## 삽입 정렬

시간복잡도 O(n^2), 안정 정렬임,

> - 데이터셋 A 에서, A[1] 을 꺼냄, 1 보다 앞선 인덱스(현 단계에서는 0 인덱스만 있음) 안에서 A[1] 이 오름차순 들어갈 위치를 찾아 삽입,
> - 위 첫번째 단계 결과, 0 ~ 1 인덱스 원소들이 정렬됨,
> - 이번에는 A[2] 를 2 보다 앞선 인덱스(0 ~ 1 인덱스)에서 A[2] 가 오름차순으로 들어갈 위치를 찾아 삽입,
> - 두번째 단계 결과, 0 ~ 2 인덱스 원소들이 정렬됨,
> - ...
> - A[N] 을 꺼냄, N 보다 앞선 인덱스(0 ~ N-1)에서 A[N] 이 오름차순으로 들어갈 위치를 찾아 삽입,
> - N 번째 단계 결과, 0 ~ N-1 인덱스 원소들이 정렬됨,

`위치를 찾아 삽입` 이라는 것을 코드로 좀 더 디테일하게 N 단계의 케이스를 가지고 나타내면 아래와 같음,

> - N 단계에서, A[N] 을 다른 변수로 key 로 꺼냄, (이 결과 A[N] 은 비어있게 됨)
> - 삽입된 위치를 찾을 땐, N-1 -> N-2 -> N-3 ... 과 같이 N 보다 바로 앞부터 시작해서 더 앞으로 비교를 진행하면 됨,
> - A[N-1] 과 key 를 비교, A[N-1] <= key 라면, key 를 A[N] 에 삽입하고 단계 종료,
> - 아니라면 A[N-1] 을 A[N] 에 삽입, (이 결과 A[N] 은 채워지고, A[N-1] 은 비어있게 됨),
> - A[N-2] 와 key 를 비교, A[N-2] <= key 라면, key 를 A[N-1] 에 삽입하고 단계 종료,
> - 아니라면 A[N-2] 를 A[N-1] 에 삽입, (이 결과 A[N-1] 은 채워지고, A[N-2] 은 비어있게 됨),
> - ...
> - A[0] 과 key 를 비교, A[0] <= key 라면, key 를 A[1] 에 삽입하고 단계 종료,
> - 아니라면 A[0] 을 A[1] 에 삽입, (이 결과 A[1] 은 채워지고, A[0] 은 비어있게 됨),
> - A[0] 에 key 를 삽입하고 단계 종료,

좀 복잡하기는 하지만, 연필로 도식화해가며 따라가보면, 충분히 이해가 될 거임,

python 코드로 나타낸 풀이는 아래와 같음,

```python
class Solution:
    def sortArray(self, nums: List[int]) -> List[int]:
        for i in range(1, len(nums)):
            key = nums[i]

            for j in range(i-1, -1, -1):
                if nums[j] <= key:
                    nums[j+1] = key
                    break
                else:
                    nums[j+1] = nums[j]
            else:
                nums[0] = key

        return nums
```

이중루프 사용, 안쪽루프의 if 구문을 보면, `nums[j] <= key` 가 아닐때만 종료되지 않고 순회가 이어지기 때문에, 동일한 크기를 가지고 있던 원소들이 다른 동일한 크기를 가진 원소의 앞쪽으로 이동하여 삽입될 수 없음, 원래 순서가 바뀌지 않기 때문에 안정 정렬이 됨,

## 기수 정렬

시간복잡도 O(dn), d 는 정렬하고자 하는 원소의 최대 자릿수임, 그리고 안정 정렬,

> - -9 ~ 9 까지 이름이 붙은 bucket 을 준비,
> - 첫번째 단계에서 각 원소의 제일 뒷자리와 일치하는 bucket 에 순서대로 원소를 삽입,
> - -9 부터 9 까지 bucket 번호 순서대로, 그리고 동일한 bucket 안에서는 삽입되었던 순서대로 nums 를 다시 채움,
> - 두번째 단계에서 각 원소의 제일 뒤에서 두번째자리와 일치하는 bucket 에 순서대로 원소를 삽입,
> - 첫번째 단계에서 실행했던, bucket 안의 숫자들을 nums 에 다시 채우는 과정 실행,
> - 가장 자릿수가 큰 원소의 제일 높은 자릿수까지 진행한 뒤 종료,

bucket 이라는 특수한 자료가 사용되는데, 예를들면, `[10, 234, -5, 4]` 가 있다고 하면...

> - 첫번째 단계에서, -5 bucket 에는 -5 가, 0 bucket 에는 10 이, 4 bucket 에는 234, 4 가 채워지고, bucket 순으로 nums 에 다시 나열하면, `[-5, 10, 234, 4]` 가 됨,
> - 두번째 단계에서, 0 bucket 에는 -5, 4 가, 1 bucket 에는 10 이, 3 bucket 에는 234 가 채워지고, bucket 순으로 nums 에 다시 나열하면, `[-5, 4, 10, 234]` 가 됨,
> - 세번째 단계에서, 0 bucket 에는 -5, 4, 10 이, 2 bucket 에는 234 가 채워지고, bucket 순으로 nums 에 다시 나열하면, `[-5, 4, 10, 234]` 가 됨,

가장 큰 자릿수인 234 의 가장 높은 단계인 세번째 단계까지 진행하였다면 종료,

이 정렬은 다른 정렬 방법과는 다르게 원소간의 크기 비교가 없음, 다만 자릿수 개념이 등장하기 때문에, 정수 나 문자열(이 경우는 bucket 을 문자열 단위로 준비해야 함)로 이뤄진 데이터셋만 정렬이 가능하다는 특징이 있음,

이 알고리즘을 python 코드로 나타내면 아래와 같음,

```python
class Solution:
    def sortArray(self, nums: list[int]) -> list[int]:
        return radixSort(nums)

def cdiv(x: int, y: int) -> int:
    return int(x / y)

def cmod(x: int, y: int) -> int:
    return x - cdiv(x, y) * y

def radixSort(nums: list[int]) -> list[int]:
    for exp in itertools.count(0):
        bucket = {}
        r = 10 ** exp
        has_more = False

        for n in nums:
            a = cdiv(n, r)
            if a != 0:
                has_more = True 

            b = cmod(a, 10)
            bucket.setdefault(b, []).append(n)

        if not has_more:
            break

        nums = []
        for x in range(-9, 10):
            if x in bucket:
                nums.extend(bucket[x])

    return nums
```

주의할 점이 있는데, **python 은 음수의 경우 몫을 구하는 // 연산자와 나머지를 구하는 % 연산자가 다른 프로그램 언어와는 다른 결과**를 보이기 때문에, 위 코드에서도 몫을 구하는 cdiv 함수와 나머지를 구하는 cmod 함수를 따로 정의해 두었음,

어떤 식으로 다르게 동작하는지 알고 싶다면, ai 에 질문해보는 것이 가장 빠름,

코드에서 r 은 0, 10, 100, 1000, ... 식으로 반복할 때마다 증가, 원소를 r 로 나눈 나머지는 자릿수에 어떤 숫자가 있는지를 나타냄,

매 반복마다 원소를 r 로 나눈 몫이 모든 원소에 대해 0 이라면, 제일 높은 자릿수를 가진 원소의 제일 큰 자리 단계를 통과했다는 의미이기 때문에 has_more 스위치를 사용하여 루프를 탈출하도록 되어 있음

동일한 크기의 원소라면, bucket 에 채우는 순서, 그리고 다시 nums 에 채우는 순서가 뒤바뀌지 않기 때문에 안정 정렬이 됨,
