## 사전 준비

ai 시대가 열린 이후, 검색/간단한 분석/이미지 생성 등에만 활용하다가, 회사 업무 관련해서 vibe 코딩을 시도한 적이 있음, 결과는 신세계,

마침 내 블로그도 리뉴얼해볼까 생각이 들었음, 예전같았으면 라이브러리나 함수 사용법 정도로만 ai 활용하면서 직접 코딩했겠지만, 본인은 자연어로만 지시내리고 **대부분의 코드를 ai 가 직접 작성토록 하는 vibe 코딩**으로 해보자 생각이 들었음,

그냥 웹브라우저에서 ai 웹사이트 들어가서 이래저래 코드작성 지시할 수도 있겠지만, 내가 코드를 다운로드 받거나 copy & paste 를 계속 해줘야하는 귀차니즘이 꽤 있음, 그래서 cli 버전을 사용하기로 함,

결과부터 말하자면, [Codex CLI](https://learn.chatgpt.com/docs/codex/cli) 무료 버전 사용하여 개인 블로그 MVP 버전 제작, google 계정 두개 월 사용량 거의 꽉차게 사용해서 완성했음, (codex cli 설치, 인증(로그인), 기본적인 사용 방법은 포털에서 검색하거나, 웹버전 ai 에게 물어보기 바람)

처음에는 무료 사용량이 빠방하다고 알려진 [Gemini CLI](https://geminicli.com/) 를 사용해보려 했는데, 더 이상 개인버전에서는 인증(로그인)이 안된다는 메세지가 계속 떠서 걍 포기,

codex cli 는 powershell 터미널에서 구동하였고, codex cli 가 작성해준 코드를 보고 짜잘한 건 직접 타이핑하기 위해 편집기로 [Visual Studio Code](https://code.visualstudio.com/) 사용함,

그리고 완성된 블로그가 배포될 곳으로 github page 를 생각했기 때문에, [Github](https://github.com) 에 미리 블로그용 레포지토리를 생성해 둠,

## AGENTS.md

보통 웹버전 ai 의 경우 채팅했던 내용을 다시 끄집어내어 이어갈 수 있음, cli 버전의 경우도 이어서 실행하기 같은 것을 실행옵션으로 제공하기는 함, 하지만 그것보다는 이제까지 작업 내용을 ai 로 하여금 AGENTS.md 에 기록하게 하고, 새로 시작할 땐 이 파일을 읽으라고 하는 것이 제일 무난했던 것 같음,

AGENTS.md 가 뭔지 모른다면 [나무위키](https://namu.wiki/w/AGENTS.md) 참고, 간단히 말하자면 **ai 를 위한 readme.md** 와 같은 파일이라 보면 될 듯, 중간에 틈틈히 codex cli 에게 현재까지 진행한 내용을 AGENTS.md 에 업데이트 하라고 이야기 하면서 vibe 코딩 진행했음,

AGENTS.md 파일을 열어보면, vibe 코딩 주요한 지시사항들이 고스란히 잘 담겨 있음, 앞으로도 vibe 코딩과 관련된 경험을 종종 포스팅할 건데, 본인이 지시한 프롬프트를 일일이 나열하기 보다는 AGENTS.md 파일 안의 주요한 내용을 보여주면 좋을 것 같음,

## 기술 스택

아래는 기술 스택 관련하여, AGENTS.md 에 담겨져 있는 내용임,

```markdown
- Astro `7.3.1`
- Pico CSS `2.1.1` (`@picocss/pico`)
- YAML 파서 `yaml` (`2.9.0`)
- 의존성은 npm으로 관리합니다.
```

내게 익숙한 프레임워크를 사용해야 지시도 잘 할 수 있을 것 같아서, 가끔 사용해왔던 [Astro](https://astro.build/) 프레임워크로 SSG 사이트 구축하겠다고 했음,

요새는 [TailwindCSS](https://tailwindcss.com/) 같이 CSS 를 원자단위로 분석해서 클래스화한 프레임워크를 많이 사용하겠지만, 귀차니즘으로 이미 완성되어있는 디자인에 살짝 변형만 가하는 것이 좋을 것 같아 [Pico CSS](https://picocss.com/) 를 사용하기로 함,

본 포스팅 작성 시점에 보이는 디자인은 대부분 pico css 에 사전 정의된 디자인이며, 본인은 단락 간격 조절이나 폰트, 이모티콘 정도만 가미하였음,

본 블로그 우상단에 보면 메뉴가 보이는데, 그 중 `BLOG` 를 클릭하면 나오는 전체 포스팅 목록의 순서를 위해 별도로 `blog.yaml` 라는 설정파일을 두기로 했는데, codex cli 가 astro 는 네이티브로 yaml 을 임포팅 못한다고 하면서 스스로 yaml 의존성을 추가하였음,

## astro 프로젝트 구조

아래는 프로젝트 구조와 관련된 AGENTS.md 내용임,

```markdown
- `src/components/Base.astro`: 기본 HTML 문서 구조, Pico CSS 전역 import, 공통 헤더/푸터와 `<slot />`을 담당합니다. 사용자가 수정한 내비게이션 링크는 보존합니다.
- `src/components/Post.astro`: `title`, `description`, `updated`를 `Astro.props`로 받아 slot을 렌더링하는 글 레이아웃입니다.
- `src/content/index.md`: 홈페이지 콘텐츠이며, 블로그 글 목록과 개별 글 경로 생성에서 제외합니다.
- `src/content/<category>/`: 블로그 Markdown 글을 둡니다.
- `src/blog.yaml`: 블로그 카테고리 메타데이터입니다.
- `src/pages/index.astro`: `src/content/index.md`를 import하고 frontmatter를 `Post`에 전달합니다.
- `src/pages/blog.astro`: `/blog`의 카테고리 안내문, 접이식 카테고리별 글 목록, 제목 검색·강조 기능을 담당합니다.
- `src/pages/blog/[...slug].astro`: 개별 정적 글 페이지를 생성합니다.
```

웹페이지 주소는 `src/pages` 에, 마크다운 형식의 블로그 포스팅 소스들은 `src/content` 에, 웹페이지를 구성하는 컴포넌트들은 `src/components` 에 리소스들이 모여있는 구조임, 최신 프론트엔드 프레임워크의 기본 구조를 알고 있다면 어느정도 이해가 될 것임,

콘텐츠는 카테고리를 구분, `src/content/[카테고리이름]` 폴더에 각 카테고리에 해당하는 마크다운 포스팅들을 위치시키도록 구성함,

블로그 mvp 버전은 웹브라우저에서 `http(s)://도메인/blog` 에 접근하면, 전체 포스팅을 보여주고, 제목으로 포스팅을 검색하는 기능이 담겨 있음, 그리고 각 포스팅의 주소는 `https(s)://도메인/blog/슬러그` 가 되도록 함, (슬러그는 아래에서 설명)

## 포스팅 마크다운

아래는 마크다운 형식으로 저장되어있는 각 포스팅들과 관련된 AGENTS.md 내용임,

```markdown
- 모든 `.md` 파일의 frontmatter는 `title`, `description`, `updated` 필드만 사용합니다.
- 블로그 글 파일명은 `[순번]slug.md` 형식입니다.
  - `[순번]`은 카테고리 목록 정렬용이며 URL에 포함하지 않습니다.
  - `slug`만 사용해 `/blog/slug` 정적 페이지를 생성합니다.
  - `[순번]` 형식이 아닌 파일과 루트 `src/content/index.md`는 개별 글 페이지 생성에서 제외합니다.
  - 모든 글의 slug는 전체 사이트에서 고유해야 합니다. 중복 시 빌드가 실패합니다.
```

포스팅의 순서를 어떻게 지정할까 고민하다가, md 파일의 형식을 `[순서번호]슬러그.md` 로 하기로 함, 순서번호는 포스팅 순서를 나타내고, 슬러그는 해당 포스팅의 웹주소에 반영함,

## 전체 포스팅 나타내는 웹페이지 구조

아래는 본 블로그 우상단 `BLOG` 메뉴를 클릭했을 때 나오는 페이지 구현과 관련된 AGENTS.md 내용임,

```markdown
- `src/blog.yaml`의 각 항목은 `id`, `name`, `order`를 가집니다.
  - `id`: `src/content/` 하위 카테고리 폴더명
  - `name`: `/blog` 화면에 표시할 카테고리명
  - `order`: 파일명 순번의 정렬 방향으로 `asc` 또는 `desc`
- `/blog`에는 YAML에 정의된 카테고리만 표시합니다.
- YAML에 등록된 카테고리의 폴더가 없거나 글이 없으면 안내문을 표시합니다.
- 카테고리는 처음에 접힌 상태이며, 카테고리 제목을 클릭해 펼치거나 접습니다. 접힘·펼침 표식 CSS는 현재 주석 처리되어 있어 표시하지 않습니다.
- `/blog` 검색은 제목만 대상으로 합니다. Enter 또는 돋보기 버튼으로 실행하며, 일치하지 않는 글을 숨기고 일치하는 제목 부분을 `<mark>`로 강조합니다. 검색 결과가 있는 카테고리는 자동으로 펼치며, 검색어를 비우면 전체 목록을 다시 접습니다.
```

전체 포스팅을 카테고리 구분하여 표시하도록 했으며, 표시되는 카테고리와 포스팅의 순서는 `blog.yaml` 설정파일을 참조하도록 함,

또한 포스팅이 많아졌을 때, 제일 아래있는 카테고리나 포스팅들은 한눈에 담기기 어려울 수 있으므로, 처음 `BLOG` 페이지에 접근하면, 모든 카테고리가 닫혀있는 (클릭해야 해당 카테고리 포스팅들이 나타나는) 구조로 만들어달라고 했으며, 포스팅을 제목단위로 서칭할 수 있는 input text 요소도 붙이도록 함,
