## 네이트 뉴스 크롤링

기획 업무를 하다보면, 최신 트렌드를 파악하든가, 거시경제 동향이 어떻게 변하고 있다든가, 업계에 영향력을 주는 제도가 어떻게 바뀐다든가 보고를 해야할 때가 자주 있음,

과거에는 개인이 시간을 들여서 일일이 검색 등을 해야 했지만, ai 를 활용하는 시대이니만큼, 기간을 설정하여 원하는 주제로 뉴스를 긁어 모으고, 그 결과를 ai 에 줘서 분석도 시키는 방법을 사용함,

이 포스팅에서는 **vibe 코딩으로 뉴스 크롤링하는 스크립트를 작성**해본 경험을 소개함,

우선, 크롤링 대상이 되는 뉴스 사이트를 골라야하는데, [네이트 뉴스](https://news.nate.com/)를 선택했음, 이유는...

> - 사이트가 정적웹페이지로 구성되어 있음, --> 웹페이지를 호출했을 때 최종완성된 웹페이지가 그대로 나오기 때문에 가장 기본적인 크롤링 툴 사용에 적합
> - 다른 뉴스 사이트와 달리, 네이트가 제공하는 기본 양식에 맞춘 웹페이지 형태로 제공함, --> 언론사 개별 웹페이지가 아니기 때문에 언론사마다 크롤링 대상을 일일이 맞춰줘야할 필요가 없음,
> - 사이트 자체가 크롤링에 민감하게 반응하지 않음, --> 매우 빠른 간격으로 사이트를 헤집고 다닌다면, bot 같은 것으로 생각해서 접근을 차단하는, 구글이나 네이버 같은 사이트들이 많은데, 네이트는 아직까진 차단당한 경험이 없음,

간단히 요약하면, 웹사이트 구조가 정적으로 단순하고, 단일 양식이고, 크롤링 위한 접근에 관대하기 때문임, (제발 계속 이 정책을 네이트가 유지해 줬으면 함)

## 크롤링 사전 준비

ai 에게 크롤링 스크립트 만들어달라고 하려면, 사전에 내가 html / js / css 같은 지식을 알고 있는 게 유리함, 예를들어 단순하게 "뉴스 제목을 크롤링 해줘" 보다는 "h1#news-title 엘리먼트를 찾아서, 그 엘리먼트의 textContent 를 크롤링해줘" 같이 자세히 지시하는 것이 오류 확률이 적음,

자세한 지시를 위해 네이트 뉴스 웹페이지 구조를 브라우저 개발자도구를 통해서 먼저 뜯어보아야 함, 그리고 이리저리 내가 수작업으로 크롤링을 한다고 치고, 어떻게 행동해야하는지 파악을 해야 함,

네이트 뉴스는, 뉴스를 검색하는 페이지와 어떤 뉴스 자체를 보여주는 페이지 크게 둘로 나뉨, 그래서 **뉴스 리스트를 수집**하는 스크립트와 링크를 찾아다니며 **뉴스 본문을 수집**하는 스크립트, 총 2 개를 작성해야겠다고 생각함,

ai 는 [Copilot CLI](https://github.com/features/copilot/cli?locale=ko-kr) 무료 버전을 사용, 그리고 작업 중간중간 틈틈히 AGENDTS.md 업데이트를 지시하였음, 본인이 지시한 프롬프트 자체 보다는 ai 가 작업수행을 종합한 프롬프트인 AGENTS.md 내역으로 대신함,

아래는 AGENTS.md 에 기록된 전체 프로젝트 개요임,

```markdown
## 프로젝트 현황

이 프로젝트는 네이트 뉴스 크롤링을 2단계로 나누어 처리하는 구조로
개발 중입니다.

1. 검색어와 검색 기간으로 네이트 뉴스 검색
2. 검색 결과에서 말줄임 처리된 제목, 뉴스 링크, 표시 날짜 수집
3. 수집 결과를 CSV 파일로 저장

첫 번째 단계인 검색 결과 목록 크롤러와 두 번째 단계인 각 뉴스 링크 접속
후 완전한 제목과 본문 수집 크롤러가 구현되어 있습니다.
```

기술 스택은 아래와 같음,

```markdown
## 개발 환경 및 의존성

- Python: `>=3.12`
- 패키지 관리 및 실행 도구: `uv`
- HTML 파서: `beautifulsoup4`
- HTTP 클라이언트: `requests`
- CSV 저장: Python 표준 라이브러리 `csv`
```

정적 웹페이지이기 때문에, python 에서 기본 크롤링 교육 과정에 항상 언급되는 beautifulsoup4 라이브러리 사용, 개인적으로 uv 패키징 툴 선호하기 때문에 ai 에게 uv 사용하겠다고 하여 포함시킴, 나머지는 ai 가 판단하도록 했음,

## 뉴스 리스트 수집 스크립트

AGENTS.md 에서 중요한 사항들만 아래에 언급함,

````markdown
크롤러는 다음 형식의 검색 URL을 생성합니다.

```text
https://news.nate.com/search?q={query}&f3=2&ps=3&ps1={start_date}&ps2={end_date}&o=T&page={page}
```

검색 페이지 1부터 100까지 순서대로 접속하며, 페이지의
`ul.search-list li` 요소가 없으면 더 이상 수집하지 않고 종료합니다.
페이지 요청 사이에는 1초의 대기 시간을 둡니다.
````

네이트 뉴스 검색 결과를 "제목"만 포함, "기간"을 설정, "최신순"으로 정렬하고자 했음, 이 방식에 따른 네이트 뉴스 검색 주소 형태는 위에 언급된 것과 같음,

그리고 중요한 점은, 기사가 한 페이지에 15 개 나오는데, **최대 100 페이지까지만 노출**된다는 점임, 101 페이지를 요청해보면, 100 페이지와 동일한 페이지를 계속 띄움, 이 부분은 내가 어떻게 할 수 있는 것이 아니기에, 만일 원하는 기간의 뉴스 웹페이지 개수가 100 을 넘는다면 기간을 조정하든가 해야 함,

````markdown
각 검색 결과에서 다음 정보를 수집합니다.

- `news_date`: `span.time` 요소의 텍스트
- `news_title`: `h2.tit` 요소의 텍스트
- `news_link`: `a` 요소의 `href` 속성

`news_title`은 줄바꿈, 탭, 연속 공백 등 모든 공백 문자를 하나의 일반
공백으로 바꾸고 앞뒤 공백을 제거합니다.

`news_date`는 줄바꿈, 탭, 연속 공백 등 모든 공백 문자를 `|` 하나로
바꿉니다. 예를 들어 다음과 같이 저장됩니다.

```text
티브이데일리|2026.08.01|00:12
```
````

개발자 도구를 사용하여 보면, 생각보다 깔끔한(?) 형태로 뉴스 리스트 구조가 되어 있어 정보 수집해야하는 html 엘리먼트 구조가 복잡하지 않음, 나름 데이터 클렌징도 거치도록 함,

````markdown
CSV 컬럼 순서는 다음과 같습니다.

```text
news_date,news_title,news_link
```

CSV는 UTF-8 BOM(`utf-8-sig`) 인코딩으로 저장하므로 Excel에서 직접 열 수
있습니다. 크롤러를 새로 실행하면 기존 결과 파일을 비우고 새 결과를
수집합니다.
````

수집 결과는 csv 파일로 저장하도록 했음, 그런데 요즘 시대 인코딩은 대부분 utf-8 이지만, 엑셀은 과거 호환성 때문에 순수 utf-8 로만 저장된 csv 를 그대로 로드하면 한글이 깨지게 됨, 이를 방지하기 위해 ai 에게 적절히 조치하라고 지시했음,

## 뉴스 본문 수집 스크립트

```markdown
첫 번째 단계에서 생성한 `crawl_news_output.csv`를 입력으로 사용합니다.
입력 파일이 없으면 오류를 발생시키고 종료합니다. CSV 전체를 메모리에
올리지 않도록 20개 단위의 배치로 읽고, 배치 안의 기사를 하나씩 처리합니다.
입력 파일이 없을 때는 traceback 대신 원인과 조치 방법을 한글 안내로
출력하고 종료 코드 `1`을 반환합니다.
```

뉴스 리스트 수집 스크립트의 실행 결과 만들어지는 csv 파일(리트스 csv 파일)이 있어야 작동함, 보통은 csv 파일을 한번에 읽은 뒤 작업을 해도 무방하지만, 혹시 모를 메모리의 부담이 있을 수 있어, 배치 방식으로 작동하도록 지시하였음,

```markdown
각 `news_link`에 접속해 다음 요소를 수집합니다.

- `news_title`: 먼저 `div#articleView h1.articleSubecjt`의 텍스트를 찾고,
  없으면 `div#articleView h1.articleSubject`의 텍스트를 사용
- `news_body`: `div#articleView div#realArtcContents`의 텍스트

본문을 수집할 때 `img`와 `script` 요소는 제거합니다. 제목과 본문은
줄바꿈, 탭, 연속 공백 등 모든 공백 문자를 하나의 일반 공백으로 바꾸고
앞뒤 공백을 제거합니다.
```

뉴스 본문에 그림이나 광고와 같은 엘리먼트들이 포함되어있음, 필요 없으므로 그런 엘리먼트는 스킵하도록 하고, 본문 내용도 데이터 클렌징을 거치도록 함,

````markdown
결과는 `crawl_news_article_output.csv`에 기사 하나를 처리할 때마다
즉시 저장합니다. 결과 컬럼 순서는 다음과 같습니다.

```text
news_date,news_title,news_link,news_body
```

`news_date`와 `news_link`는 원본 CSV 값을 사용하고, `news_title`과
`news_body`는 기사 페이지에서 새로 수집한 값을 사용합니다. 기사 처리
상태는 콘솔에 표시되며, 요청 사이에는 1초의 대기 시간을 둡니다.
개별 기사 수집에 실패해도 오류를 출력하고 해당 행을 빈 제목·본문으로
저장한 후 다음 기사 처리를 계속합니다. 출력 파일은 UTF-8 BOM
(`utf-8-sig`)으로 저장되어 Excel에서 직접 열 수 있습니다.
````

뉴스 본문까지 포함된 결과를 최종 csv 로 출력하도록 함,

뉴스 리스트 스크립트에도 기사 제목은 수집 가능하지만, 실제로 웹사이트 방문해보면 너무 긴 제목에 대해서는 말줄임표를 사용하고 있음, 기사 본문의 제목에는 말줄임표가 없기 때문에 기사 제목인 `news_title` 을 뉴스 본문 스크립트에서 얻은 정보대로 업데이트 하도록 함,

이 역시 엑셀에서 바로 열 때 인코딩 문제가 없도록 처리함,

## 참고사항

나름 잘 사용했음, 그런데 주의 사항이 있는데 **중복된 기사 처리는 없다는 점**임, vibe 코딩 과정에서 생각을 하긴 했으나 굳이 필요하진 않았고 토큰 사용 절약 겸 기능을 추가하지는 않았음,

만일 100 페이지 넘어가기 때문에 일정을 조정하며 리스트 수집하다가 겹치는 경우, 다양한 키워드를 가지고 수집하여 합치는 경우와 같은 케이스에서 중복이 발생할 가능성이 있음,

이 때는, 뉴스 리스트 csv 를 그대로 ai 에 말해서, 뉴스 링크 기준으로 중복을 없애달라고 한 뒤, 그 결과를 가지고 뉴스 본문 스크립트 진행하는 것이 효율적일 것임,
