# 바이브코딩: 상권(음식점 밀집도)의 세기를 지도에 시각화

직전 [포스팅](https://wikidocs.net/blog/@znkblog/32558/)에서 바이브코딩으로 상권의 측정과 상권-매출의 상관관계 분석하는 경험을 소개했었다.

다음으로 회사 경영진은 **상권의 세기를 나타내는 1km² 단위의 격자안에 포함된 음식점 수(단위면적 당 음식점 밀집도)가 우리나라에 전반적으로 어떻게 분포**가 되어있는지를 한눈에 보고 싶어 했다. 즉 시각화 자료를 원했다.

히트맵이 떠올랐다. 전국 지도를 바탕에 깔고, 그 위에 격자를 좌표에 맞도록 배치하고, 격자 안의 음식점 수를 구간별로 색을 달리해서 약간 반투명으로 보여지게 하면 되겠다 싶었다. html 파일로 만들어서 웹브라우저에서 쉽게 열 수 있도록 하면 사내 배포도 큰 문제 없을 것 같았다.

copilot 무료버전을 사용하여 바이브코딩으로 전반적인 html 초안을 작성했다. 중간에 지도와 격자 좌표가 어긋나는 문제가 있었는데 copilot은 이를 잘 해결하지 못해 중간에 codex로 바꿔서 최종 마무리하였다.

아래부터는 ai가 스스로 작성하도록 한 AGENTS.md 파일 중 주요 내용을 바탕으로 작업한 내용을 소개해본다.

## 프로젝트 개요와 기술스택

```markdown
EPSG:5174 좌표로 정의된 격자별 음식점 수를 한국 지도 위에 시각화하는 단일 HTML 지도다. 사용자는 HTML 파일을 브라우저에서 열어 격자 분포를 살펴보고, 격자를 클릭해 격자 ID와 음식점 수를 확인할 수 있다.
```

직전 [포스팅](https://wikidocs.net/blog/@znkblog/32558/)에 있는 두번째 스크립트를 실행하면 `격자배치결과.csv`라는 파일이 생성된다. 여기는 격자의 좌표와 좌표별 음식점 수가 기록되어 있다. 이 파일을 가져와서 단일 html 파일을 만들도록 주문했다.

```markdown
- **HTML/CSS/JavaScript**: 지도 화면, 왼쪽 범례, 상태 메시지와 상호작용을 한 파일에 구현한다. `file://` 실행에서 스타일 누락이 발생하지 않도록 Leaflet CSS도 HTML에 직접 포함한다.
- **Leaflet 1.9.4**: 웹 지도, 지도 이동·확대/축소, 배경 타일 및 격자 타일 레이어를 담당한다.
- **좌표 사전 변환**: 격자 모서리 좌표는 EPSG:5174에서 EPSG:3857로 미리 변환하여 HTML에 압축된 자료로 포함한다. 브라우저에서 proj4js를 실행하지 않는다.
- **배경 지도**: `file://`에서 직접 열 때 Referer 제한으로 차단되지 않는 `https://tile.openstreetmap.de/{z}/{x}/{y}.png`의 OpenStreetMap 타일을 사용한다. Leaflet은 unpkg CDN에서 불러온다.
- 결과물은 별도 CSV·CSS·JavaScript 파일이나 웹 서버가 필요 없는 단일 HTML이다. `file://`로 직접 열 수 있어야 한다.
- Leaflet JavaScript와 배경 지도 타일은 외부에서 불러오므로 실행 시 인터넷 연결이 필요하다. API 키는 사용하지 않는다. JavaScript CDN에는 SRI 무결성 속성을 적용하고, 지도에는 OpenStreetMap 저작자 표시를 항상 노출한다.
```

[leaflet](https://leafletjs.com/)은 모바일이나 웹페이지에서 지도를 손쉽게 넣을 수 있도록 도와주는 오픈소스 라이브러리이다. 무료에 특별한 회원등록 절차도 없고 다른 지도 라이브러리처럼 키를 요구하지도 않아 종종 사용한다. 여기서도 사용하도록 주문했다.

배경으로 깔리는 지도는 ai가 스스로 선택하도록 했다. 배경 지도의 좌표계(EPSG:3857)가 격자들의 좌표계(EPSG:5174)와 달라 이를 맞추도록 해야했다. 처음에는 ai가 [proj4js](https://proj4js.org/)라는 좌표계 상호변환 라이브러리를 심고 동적으로 좌표계를 변환했었으나, 웹페이지 로딩 속도가 느려서, 변환을 미리 한 뒤 그 데이터를 직접 심는 것으로 바꾸었다.









# 프로젝트 개요

EPSG:5174 좌표로 정의된 격자별 음식점 수를 한국 지도 위에 시각화하는 단일 HTML 지도다. 사용자는 HTML 파일을 브라우저에서 열어 격자 분포를 살펴보고, 격자를 클릭해 격자 ID와 음식점 수를 확인할 수 있다.

# 데이터 및 좌표

- 원본 데이터 파일은 `격자배치결과.csv`다. CSV 칼럼은 `격자ID`, `격자좌상단좌표정보(X)`, `격자좌상단좌표정보(Y)`, `음식점카운팅`이다. X와 Y는 모두 격자 좌상단 좌표다.
- 격자 한 칸은 EPSG:5174 기준 1,000m × 1,000m다.
- 전체 격자는 X=-10,000, Y=566,000을 좌상단 원점으로 하는 556열 × 609행, 총 338,604칸이다. 열은 동쪽으로, 행은 남쪽으로 증가한다.
- 0부터 시작하는 행·열에서 좌상단 좌표는 `X=-10000+열×1000`, `Y=566000-행×1000`으로 계산한다.
- 격자 ID는 행 우선 순서로 `G${String(행×556+열+1).padStart(6, "0")}`로 계산한다. 첫 셀은 `G000001`, 마지막 셀은 `G338604`다.
- 음식점 수 범위는 0~1,564다. 원본 CSV에서 음식점 수가 1 이상인 격자는 25,916칸이고 음식점 수 합계는 655,071개다.
- CSV 데이터는 `음식점격자지도.html` 내부에 직접 포함한다. 파일 크기를 줄이기 위해 음식점 수가 0인 행은 포함하지 않는다. 생략된 셀은 음식점 수 0으로 취급하고 투명하게 표시한다.
- CSV의 X는 동쪽 방향 좌표(easting), Y는 북쪽 방향 좌표(northing)로 취급하고 변환 입력 순서는 `[X, Y]`다. 두 값 모두 셀 좌상단 좌표다.
- EPSG:5174의 Korean 1985 datum 변환을 포함해 전체 격자 모서리 `(556+1)×(609+1)=339,770개`를 EPSG:3857로 미리 변환한다. 변환값은 0.1m 정수로 반올림하고, 각 행의 첫 점은 두 개의 little-endian Int32, 이후 점은 직전 점과의 X/Y 차분 두 개의 little-endian Int16으로 저장한 뒤 Base64로 HTML에 포함한다.
- 브라우저는 내장 좌표를 복원해 격자를 그리며 proj4js 좌표 변환을 실행하지 않는다. 복원 바이트 수와 꼭짓점 수가 예상값과 다르면 지도를 초기화하지 않고 경어체 오류를 표시한다.

# 지도 동작 및 표시 규칙

- 음식점이 있는 셀은 반투명한 색상으로 표시하고, 음식점 수가 0인 셀은 완전히 투명하게 둔다.
- 왼쪽 범례는 투명한 0개 항목과 5개의 양수 구간으로 구성한다. 초기 구간은 `1–10`, `11–50`, `51–100`, `101–200`, `201–1564`다.
- 범례에서 처음 네 구간의 상한값을 편집할 수 있다. 값은 오름차순의 정수여야 하며, 유효하지 않은 변경은 적용하지 않는다.
- 격자 표시는 커스텀 Leaflet `GridLayer`에서 지도 타일 단위로 그린다. 지도를 이동하거나 확대·축소할 때 격자가 배경 지도와 함께 움직이고 크기가 바뀌어야 한다.
- 타일과 전체 격자 범위가 겹치지 않으면 셀을 순회하지 않고 빈 투명 타일을 반환한다.
- 전체 변환 격자망에서 클릭 위치를 역산해 격자 ID와 음식점 수를 팝업에 표시한다. 음식점이 0인 격자도 계산된 ID와 `0개` 정보를 확인할 수 있다. 전체 격자 밖을 클릭하면 팝업을 표시하지 않는다.
- 셀 경계에서는 왼쪽·위쪽 셀 경계를 포함하고 오른쪽·아래쪽 경계를 제외하는 `Math.floor` 규칙을 사용한다.
- 행정구역 경계와 검색 기능은 현재 구현 범위에서 제외한다. 팝업은 격자 ID와 음식점 수 표시 용도로만 사용한다.
- HTML에 표시되는 제목, 안내, 상태 및 오류 문구는 경어체로 작성한다.

# 작업 지침

- 사용자가 명시적으로 진행을 요청하기 전에는 시각화 파일을 만들거나 조사하지 않는다.
- 데이터 구조, 좌표 원점, 격자 크기, 전체 행·열 수를 변경할 때는 코드의 파싱·렌더링·클릭 계산 및 이 문서를 함께 갱신한다.
- CSV 최적화 시 0개 셀의 투명 표시와 전체 격자 ID 계산 동작을 보존한다.
- 렌더링을 수정한 뒤에는 스크립트 문법과 다음 불변값을 검증한다: 전체 셀 338,604개, 양수 셀 25,916개, 최대값 1,564, 합계 655,071, 꼭짓점 339,770개, 첫 ID `G000001`, 마지막 ID `G338604`.
- Chrome·Edge·Firefox에서 `file://`로 열어 초기 전국 화면과 여러 확대 수준에서 격자 표시, 이동·확대/축소 정합성, 타일 경계, 양수·0개 셀 클릭, 범례 경계값 변경 및 잘못된 입력 거부를 확인한다.
